# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

boneseg is few-shot segmentation of bone microscopy images (Imaris/TIFF/PNG stacks) with frozen DINOv2 features, served as a local web app, plus a paper-style evaluation in `paper/`. README.md covers user-facing features, CLI usage and the environment variables (`BONESEG_*`).

## Commands

Use the project venv (`.venv`, Python 3.14). A bare `python` is often not it, which shows up as `ModuleNotFoundError: numpy`.

```bash
.venv/bin/pip install -e . --no-deps          # Installs the package and the `boneseg` command; extras: .[sam], .[microsam], .[dev]
.venv/bin/python -m boneseg serve --open      # App at http://127.0.0.1:8000; --data-dir (default projects/)
.venv/bin/python -m pytest tests --ignore=tests/e2e -q        # Unit + API tests (about 1 min)
.venv/bin/python -m pytest tests/test_api.py -k agree_with_sam  # A single test
.venv/bin/python -m pytest tests/e2e -q       # Playwright browser tests; Chromium only launches with the sandbox disabled
```

- Tests use synthetic images and the fast `classic` backbone (`SETTINGS = {"backbone": "classic", ...}` in `tests/test_api.py`). Heavy models (DINOv2 fine-tuning, SAM, micro-SAM) are monkeypatched with stubs. `tests/test_bugfixes.py` holds regression tests named after bug-report numbers.
- Piping pytest into `tail` hides its exit code. Check the result before committing.
- There is no build step or linter config. CI is in `ci/github-actions-tests.yml`, not yet enabled (see `ci/README.md`).

## Architecture

**Data flow.**
1. `boneseg/io.py` opens files lazily as (channel, z, y, x) volumes.
2. `store.py` holds datasets, planes and embeddings (LRU caches with byte limits), labels and annotations (atomic JSON writes under `file_lock`), profiles and background jobs (a thread pool).
3. `backbone.py` turns a plane into DINOv2 patch features (`Embedding`). `segment.py` turns clicks into prototypes, scores, a threshold calibrated from the clicks, clean-up and uncertainty.

**Segmentation routes.**
- **Clicks:** `segment.py`.
- **Learned model:** `head.py`, a linear or MLP classifier on frozen features, optional z-context from neighbouring slices, threshold calibrated on held-out labels.
- **Fine-tuned DINOv2:** `finetune.py`. The result becomes a backbone id `dinov2_s14@<path>`.
- **SAM / micro-SAM on the clicks:** `sam.py`, through settings `sam_refine` ("agree"/"replace") and `sam_model`.
- **micro-SAM fine-tuned on labels:** `microsam.py` is the app side (Kaggle package export, weights-only checkpoint import, local prediction). `microsam_core.py` is the self-contained training and prediction code, also pasted verbatim into the Kaggle notebooks, so keep it free of boneseg imports.
- **Whole stacks:** `pipeline.run_stack`, taking `head=`, prototypes or `segment_fn=`. Several structures: `run_stack_multi`.

**Web API.**
- `boneseg/api/__init__.py:create_app` registers one router module per area: datasets, segmentation, learning, microsam, analysis, profiles, study, batch.
- Every router receives an `AppContext` (`api/context.py`) wrapping the `Store`.
- GPU work is serialized with `store.compute_lock`.
- Security middleware: TrustedHost, same-origin check on writes, optional token. Model files are loaded with `torch.load(weights_only=True)`.
- Request bodies live in `api/models.py`. Settings travel as a dict and are validated by `SegmentationSettings.from_dict` (`segment.py`). The page exposes only `backbone` (no control; saved per image) and `min_object_um2`; `settings()` in `static/js/core.js` fills the rest from the server's defaults. A new setting needs the dataclass field and validation check, and, to show it, a control read in `settings()`/`applySettings()` and wired in `main.js`.

**Front end.**
- `boneseg/static/` is plain HTML, CSS and JavaScript with no bundler.
- `js/*.js` are classic scripts loaded in order (`core.js` first). They share globals: the state object `S`, `$`, `api()` and `settings()`.

**Paper evaluation (`paper/`).**
- Separate from the app, it evaluates the method frozen at git tags.
- Bone measures for the evaluation (B.Ar/T.Ar etc.) are in `paper/histo.py`; histomorphometry is no longer part of the app.
- `common.py:load_sample` gives the fixed development and test slices of the Liu samples A, C, D, E and F. Sample D is read remotely from Kaggle via `remote_d.py`, with slices cached in `data/liudata/D_slices.npz`.
- `methods.py` wraps every compared method. `analyze.py:hier_boot` gives hierarchical bootstrap CIs.
- Results go to `paper/results/*.csv|md` and figures to `paper/figures/`. paper/README.md documents the protocol and results.
- GPU runs are Kaggle notebooks generated by `paper/kaggle_finetune_sam/make_kernels.py`; re-run it after edits and never hand-edit the notebooks. It covers the SAM fine-tuning kernels (finetune-SAM pinned commit) and the micro-SAM kernels. `export_setup.py` freezes folds and prompts into `setup.json`. Kaggle outputs are scored by `finetune_sam_score.py` (`--out microsam.csv` for micro-SAM).

## Constraints

- The user pushes Kaggle kernels themselves (it spends their GPU quota). Prepare them and give the `kaggle kernels push -p ...` command; do not push.
- Data licences:
  - Liu data and images derived from it stay out of git. `data/`, `sam_stack/`, `projects/` and `*.pt` are gitignored.
  - The NOISe osteoclast data has no licence: never commit it or images made from it.
  - SegPC is CC BY-NC-SA; cite its papers.
  - `reports/` (PDF reports with data images) stays untracked.
- Image channel: 3 in Liu file A, 4 in the others. The last channel is the expert mask.
- Code comments: short and developer-like, followable by a student with basic programming knowledge. Match the existing density.
- CHANGELOG.md gets an entry for user-visible changes.
